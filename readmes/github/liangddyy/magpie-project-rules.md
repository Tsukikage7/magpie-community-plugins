# 项目规则 · Magpie 插件

在 Magpie 的一个独立页面中，管理已有项目的 **AGENTS.md、CLAUDE.md、GEMINI.md** 和它们明确引用的 Markdown。三栏：项目、实际文档目录、单文件编辑。原地保存，不复制进 Library，不同步不同入口。

## 安装和打开

在 Magpie 插件管理中添加包含 `package.json` 的插件目录，或使用 Magpie CLI：

```powershell
magpie plugin add "<插件目录>"
```

从 GitHub 下载/克隆源码时，仓库根目录就是插件目录；源码不包含 `node_modules` 和 `release/`。本地安装前在根目录运行 `npm ci --ignore-scripts`，再选择此目录。项目没有编译步骤。

若使用已打包的 `.tgz`，先解压，再选择其中包含 `package.json` 的那一层。打包产物包含运行依赖，不需要另跑 npm；Magpie 0.1.4572 不能把本地 `.tgz` 直接当作 ESM 插件入口安装。已有开发环境中的 `release/project-rules` 是被 Git 忽略的本地安装副本，不会出现在 GitHub 源码下载中。

本项目使用 GitHub 话题自动发现，不申请社区精选列表、不提交收录 PR。仓库地址为 [liangddyy/magpie-project-rules](https://github.com/liangddyy/magpie-project-rules)，发布后也可使用 `magpie plugin add github:liangddyy/magpie-project-rules` 安装。发现页展示可能受 GitHub 索引、网络和缓存影响，详见 [发布指南](docs/publishing.md)。

安装后打开插件的「项目规则」页面即可。**不需要单独安装、启动或管理后端服务。** Magpie 自带的 Bun 插件宿主会自动运行内部 loopback 服务。不要直接用浏览器打开 `page/index.html`。源码开发时使用 `npm ci --ignore-scripts`；GitHub 插件安装由 Magpie 安装包及其固定版本运行依赖。

首版验证宿主：**Windows / Magpie 0.1.4572**。写入只开放 Windows 本地固定 NTFS 磁盘。其他平台、网络盘、UNC/WSL 路径未通过写入验收，保持只读或拒绝创建，不宣传兼容。

端口默认 `3497`。如被占用，页面明确报错，不连接或终止未知服务。在插件选项中更改 `servicePort` 后关闭再启用插件。可选 `magpiePath` 指定 Magpie CLI 完整路径；默认识别本机常规安装位置，否则使用 PATH 中的 `magpie`。改变 CLI 路径后重启插件宿主以应用。

## 使用

- 打开时自动读取 Magpie 已授权的会话目录和 Library 项目；「设置」可添加扫描父目录（每行一个绝对路径）。不替你开启授权、不读取原始 Agent 历史、不扫描全盘。
- 有规则的项目优先，暂无规则的项目靠后。按名称/路径搜索；手动刷新更新排序但保留当前编辑内容。来源失败保留已发现目录，覆盖受限和未完成扫描明确标注。
- 选择项目后，按 AGENTS.md、CLAUDE.md、GEMINI.md 的顺序自动打开根目录中首个可读入口。没有根入口则显示暂无规则，不搜索未引用的子目录入口。刷新保留当前文件与编辑内容，不重新跳回默认入口。
- 中栏按实际相对目录展示已纳管文档，文件只出现一次；目录可折叠，当前文件的祖先目录自动展开。只显示规则入口及关联 Markdown，不是完整文件浏览器。缺失的内部文档保留预期位置；外部链接和不可解析表达式不伪装成真实文件。
- 当前文件标题的「关联」按需展开引用/被引用列表、来源行号及缺失/外部/循环状态；点击可读关联文件或来源行导航，沿用保存/放弃/取消保护。外部和不可解析目标只展示，不读取或跳转；关联基于最近一次扫描，未保存修改尚未纳入。一次只编辑一份文件，没有多文件草稿或页签。
- 入口扫描只检查根目录的三个固定文件，不枚举其他目录，大型 Unity 等项目也不遍历生成文件。关联展开遇到读取失败或资源上限时，中栏底部提供可展开的「扫描未完成」原因，不在列表插入大段警告。已读取内容不会因扫描状态而截断。
- 当前文件标题的「打开文件夹」在 Windows 资源管理器中定位并选中文件；不保存、丢弃或改动编辑内容。缺失文件不可定位，请求期间按钮暂时禁用。服务确认的是启动请求，不保证窗口已显示；失败不会自动重试。
- 默认编辑源码。「预览」和「改动」按需打开；改动与**当前磁盘内容**比较，不自动保存、不静默合并。预览不执行原始 HTML，也不加载图片/远程资源或跳转文档链接。
- 点击「保存」或 `Ctrl+S`。切换项目、文件、忽略当前项目时如有修改，可保存并继续、放弃或取消。保存失败停留原文件，冲突保留编辑内容。
- 「新建入口」只允许项目根目录的三个受支持名称。缺失的内部引用可「创建并编辑」；确认框显示目标和待建目录。只创建空白文件；目标已存在时打开，绝不覆盖。
- 「设置 → 忽略当前项目」只隐藏目录，不改项目/Library。可在同一设置中勾选重新显示。忽略状态持久保存。
- 若 Magpie 自动更新其他插件并重启共享宿主，旧页面的会话会失效；顶部会说明原因并显示「重新连接」，不再只显示 `Failed to fetch`。点击会重新加载当前插件页面；有未保存内容时先取消并复制保留，或明确放弃后继续。不会自动重发请求；保存/创建仍在执行或结果待确认时禁止用重连解除锁定。

## 引用与范围

从项目根目录的三个受支持入口出发，识别正文 `@docs/style.md`、`[规范](docs/style.md#标题)` 和反引号包裹的带目录 Markdown 路径（如 `docs/style.md`）。单独反引号中的 `brief.md`、`state.md` 等裸文件名不再视为引用，避免把说明文字当成规则；但 `@brief.md`、`[说明](brief.md)` 这种明确引用仍保留，不按文件名全局拉黑。以引用文档所在目录解析。跳过代码围栏和普通散文；不展开变量、命令或通配符。循环处停止展开，共享文档仍是同一个源文件。**文档关联不等于 Agent 已加载或已生效。**

只自动读取项目内部文件。外部 URL、项目外路径、逃逸链接和独立子项目边界不读取、不提供创建。内部软链接/硬链接可在通过边界检查后只读；不能可靠往返的编码只读。文件上限 1 MiB，引用图有资源上限；设置中的父目录项目发现仍有独立扫描预算。部分结果明确显示，不能当成暂无规则。

## 安全保存与限制

版本含文件身份和内容摘要，不仅比较时间/大小。保存前复核；同目录排他临时文件写入，复制并校验 Windows ACL，再原子替换与回读；不先清空原件。保留 UTF-8 BOM，编辑已有纯 CRLF 文件时保留其换行风格。原 ACL 无法保留或环境未验证时拒绝写入。

保存/创建进行中和**结果待确认**时会锁定输入、切换与重试。请求超时、服务重启或操作记录缺失不代表写入失败。请先复制保留缓冲，确认旧执行器已经停止，再外部核对磁盘并真正退出、重启 Magpie。仅切换侧栏或收起到托盘可能保留旧页面，不算重新打开；首版不会自动跨重启判断旧操作是否终止。没有强制覆盖、自动重试或自动合并。

没有持久草稿恢复。宿主强退、崩溃、系统关闭或 iframe 被卸载可能无法显示离开提示，未保存内容可能丢失。普通路径复核不能抵御恶意同权限进程不停替换目录；原子替换不是跨进程比较交换，也不是断电恢复。

插件私有 `plugin-data/magpie-project-rules/state.json` 位于宿主提供的配置目录下（无目录输入时使用 XDG 配置目录或用户 `.config`）。仅存项目元数据、扫描范围和忽略 ID；不保存会话正文、规则全文、令牌或草稿。损坏状态保留并告警，不自动覆盖。单次服务最多跟踪 1000 个写操作，不驱逐未确认记录。

停用或卸载通过 Magpie 插件管理或 `magpie plugin off magpie-project-rules` / `magpie plugin rm magpie-project-rules`。不会撤销已经明确保存的项目改动，也不删除项目文件。

```powershell
npm ci --ignore-scripts
npm run check:contract
npm test
openspec validate project-rules-workspace --strict
```

端到端测试使用独立 headless 系统 Chrome；不会控制用户浏览器。测试只使用临时 fixture。原生验收使用隔离 Magpie HOME，不修改现用插件或项目。设计与安全细节见 `docs/` 和 `contracts/workspace-protocol.md`。
